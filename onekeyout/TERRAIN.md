# Flooded Vault terrain

## 플레이 아이디어와 현재 구현

황금 열쇠 하나를 찾아 나가는 규칙을 유지하면서 길 선택을 추가했습니다.
북서쪽 물가는 보행로의 직선·모서리·T자 분기를 익히는 구역이고, 남쪽 물가는
열쇠까지 이어지는 마른 길과 출구 쪽으로 가로지르는 물길을 비교하는 구역입니다.
동쪽 물가는 오목한 물가와 L자 보행로를 보여 줍니다.

물에서는 기본 속도 144 px/s의 55%인 79.2 px/s로 움직입니다.
마른 돌바닥과 보행로는 정상 속도입니다. 물은 통과할 수 있으며 벽과 사물의
충돌 규칙은 그대로 적용합니다. 보행로 밖으로 발이 나가면 물의 감속이 적용됩니다.
현재 지형을 HUD와 발 아래 물결로 알려 주고, 탈출 시 소요 시간을 표시합니다.
물길이 짧더라도 감속 때문에 항상 유리하지 않으므로 다른 경로로 재도전할 수 있습니다.
타이머는 일시정지·완료 상태에서 멈추고 재시작 시 초기화합니다.

## 편집과 실행의 경계

Tiled의 Terrain Sets가 Wang 정보를 보관하고 Terrain Brush가 autotiling을 수행합니다.
Wang과 autotile은 별개의 두 런타임 기능이 아니라, 연결 규칙과 그 규칙을 사용하는
편집 동작입니다. [공식 Terrain 문서](https://doc.mapeditor.org/en/stable/manual/terrain/)의
Corner/Edge 방식을 사용합니다. 물·보행로는 이 방식을 유지하며, 별도 동굴 방의 두 칸 높이
암벽은 [AUTOMAPPING.md](AUTOMAPPING.md)의 native Automapping 규칙으로 구성합니다.

| 대상 | 편집 규칙 | 런타임 속성 | 연결 순서 |
| --- | --- | --- | --- |
| `assets/tilesets/water.tsx` | Corner Wang, Shallow water / Water | `waterCorners`, 정수 0–15 | bit 0 TR, 1 BR, 2 BL, 3 TL |
| `assets/tilesets/boardwalk.tsx` | Edge Wang, Dry boardwalk / Boardwalk | `boardwalkEdges`, 정수 0–15 | bit 0 N, 1 E, 2 S, 3 W |

각 아틀라스는 32×32 px 타일 16칸입니다. 마스크 0은 Wang에서 비어 있는 상태로
취급하며, TSX에는 1–15의 비어 있지 않은 조합을 등록합니다. 보행로의 0번 타일은
연결 없는 작은 발판으로 Stamp Brush에서만 사용할 수 있습니다.
색·타일 ID·Wang 메타데이터를 런타임의 재질로 추정하지 않습니다. 브러시가 선택한
타일의 명시적 속성이 함께 로드되므로, 맵 편집만으로 이동 규칙도 따라갑니다.

물 영역은 네 모서리 값의 bilinear 보간이 0.5 이상인 부분입니다. 보행로는 중앙
14×14 px 발판과 각 변을 향한 폭 14 px의 연결부입니다. 그림도 이 규약으로 제작했습니다.
`surface.cpp`가 발 위치를 검사하며, `GameWorld`는 3 px 이하의 이동 단계마다 재질을
다시 확인합니다. 스프라이트 크기와 충돌 상자는 재질 판정에 사용하지 않습니다.
보행로는 물보다 우선하고, 벽 충돌은 두 재질 모두에 우선합니다.

Water와 Boardwalk는 선택 레이어이므로 기존 맵도 실행할 수 있습니다.
레이어는 표시·불투명도 1·오프셋 0을 유지합니다. 해당 레이어의 뒤집기, 회전,
애니메이션, tint, 잘못된 타입이나 범위의 속성은 로더가 오류로 거부합니다.
별도 모양의 새 지형 아트를 넣을 때에는 마스크 규약과 픽셀 검사를 함께 바꾸어야 합니다.

## Tiled에서 수정하기

1. `onekeyout.tiled-project`와 `assets/maps/first-room.tmx`를 엽니다.
2. `Water` 레이어와 **Shallow water → Water** terrain을 선택하고 Terrain Brush로 칠합니다.
3. `Boardwalk` 레이어와 **Dry boardwalk → Boardwalk** terrain을 선택하고 길을 잇습니다.
4. 벽은 `Walls`, Y 정렬 사물은 `Props`, 스폰·열쇠·출구는 `Objects`에서 편집합니다.
5. TMX와 수정한 외부 TSX를 각각 저장하고 **Play One Key Out** 명령을 실행합니다.
6. 저장소 루트에서 `./onekeyout/run.sh --check`로 연결·픽셀·플레이 검사를 실행합니다.

게임의 표시는 `Ground → Water → Boardwalk → Walls → Y 정렬 사물 → Foreground`입니다.
편집기에서도 물과 보행로를 벽과 Props 아래에 두세요. 보행로는 새 벽을 무시하는 다리가
아닙니다. 벽을 관통하는 통로를 만들려면 Walls의 해당 셀을 명시적으로 지워야 합니다.
맵 로더의 경로 검증은 셀 중심을 기준으로 합니다. 가운데가 막히고 가장자리로만
우회할 수 있는 통로는 현재 지원하지 않습니다.

## 재현과 자산 출처

`tools/flooded-vault-layout.json`은 이번 편집의 셀 좌표 명세입니다. 저장된 TMX가
게임의 원본이며, 이 명세를 게임 실행 때 자동 적용하거나 저작 맵을 덮어쓰지 않습니다.
기존 스폰·열쇠·출구, Props와 Ground를 보존하고 벽 5칸만 열었습니다.

아트는 기존 게임 팔레트에 맞춰 새로 만든 원본입니다. 먼저 로컬 자산 모음의 Wang/Blob
후보를 확인했지만, 기존 캐릭터·던전과의 색상 및 32 px 규약을 유지하도록 직접 제작했습니다.
외부 자산은 배포 파일에 추가하지 않았습니다.

```sh
# onekeyout/에서 실행. 출력 폴더에 같은 파일이 있으면 거부합니다.
python3 tools/create-terrain-art.py build/new-terrain-source
```

레시피는 PNG 두 장과 `terrain-catalog.json`만 생성하며 TMX·TSX는 쓰지 않습니다.
카탈로그에는 타일별 Wang 8개 인덱스와 의미 속성이 들어 있습니다.
이번 TSX 생성·Wang 등록·속성 입력·지형 칠하기·저장은 `tiled-ai`를 통해 실제 Tiled의
API와 Undo 경로로 수행했습니다. 가져온 이미지의 `image-<sha256>.png` 이름과 상대경로는
Tiled AI가 부여한 이름을 유지합니다. 별도의 런타임 XML 파서는 만들지 않았습니다.
원본 아트 레시피 `tools/create-assets.py`는 초기 방의 기록으로 유지합니다.

## 검증과 다음 아이디어

자동 검사는 두 아틀라스 32칸의 모든 픽셀에서 보이는 영역과 발 위치 판정이 일치하는지,
TSX의 의미 마스크와 Wang 연결 정의가 일치하는지, 실제 맵의 인접 변·모서리와
바깥 경계가 연결되는지 확인합니다. 원래 방과 새 방을 모두 키 이벤트로 완주하고
물·보행로·클리어 화면을 캡처합니다. 정적 연결 검사는 경로 검증이나 플레이를 대신하지 않습니다.

후속 아이디어는 아직 구현하지 않았습니다.

| 아이디어 | 재사용할 기반 | 구현 전 확인할 점 |
| --- | --- | --- |
| 배수 밸브로 물 높이 바꾸기 | 물 마스크와 이동 배율 | 지형 상태 변경 후 열쇠·출구까지 길이 남는지 |
| 부서진 보행로를 이어 지름길 만들기 | Edge Wang의 직선·모서리·분기 | 수리 전후 연결성과 발판 위 플레이어 처리 |
| 선택 보물을 둔 작은 섬 | Corner Wang의 오목한 해안 | 필수 열쇠 경로와 선택 탐험 경로를 구분 |
| 방별 탈출 기록과 다음 방 | 시간 표시와 TMX 로더 | 로딩·재시작·완료 상태 전환을 먼저 검증 |
